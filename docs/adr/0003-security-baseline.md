# ADR-0003: Security baseline for the WebView

- **Status:** Accepted
- **Date:** 2026-09-30
- **Amended by:** ADR-0007 (workspace command permissions, Rust-only plugins)

## Context

PolyPad executes arbitrary user code and renders results that may contain attacker-controlled
text or HTML. The WebView must be treated as an untrusted boundary: a script injected into it
must not be able to reach commands, files or secrets it was not explicitly granted.

## Decision

**Content Security Policy** (`src-tauri/tauri.conf.json`, `app.security.csp`):

| Directive | Value | Why |
|---|---|---|
| `default-src` | `'self'` | Nothing remote by default. |
| `script-src` | `'self'` | No inline scripts and no `unsafe-eval`; Tauri adds hashes for its own scripts at build time. |
| `style-src` | `'self'` | Vite extracts CSS to files in production. |
| `img-src` | `'self' data: blob:` | Icons and future chart/image results. |
| `font-src` | `'self'` | Fonts are bundled; Vite is configured never to inline them as `data:` URIs. |
| `connect-src` | `ipc: http://ipc.localhost` | Tauri IPC only. |
| `worker-src` | `'self' blob:` | Monaco workers (Phase 1). |
| `object-src`, `frame-src` | `'none'` | No plugins or frames. |
| `base-uri`, `form-action` | `'none'` | Blocks base-tag and form-based exfiltration. |

`devCsp` relaxes `script-src`/`style-src` with `'unsafe-inline'` and allows the Vite HMR
websocket **only in development** (the React refresh preamble and injected styles are inline).

**Other hardening:** `freezePrototype: true` (prototype pollution cannot change built-ins).

**Capabilities:** app commands are declared in `AppManifest::commands` (`src-tauri/build.rs`),
which turns each into an `allow-<command>` permission. Without that list every registered
command would be callable from every window. `capabilities/main-window.json` grants the main
window exactly the commands the UI uses — today only `allow-app-info`, and no core plugin
permissions at all. The generated `src-tauri/permissions/autogenerated/*.toml` files are
committed so permission changes are visible in review.

## Consequences

- Each new command or plugin permission must be added to the capability file with a
  justification in the pull request.
- Monaco and `monaco-languageclient` (Phases 1 and 6) will test this policy: Monaco injects
  `<style>` elements at runtime and `@codingame/monaco-vscode-api` uses WebAssembly for TextMate
  grammars (`'wasm-unsafe-eval'`). Any relaxation will be the minimum required and recorded in a
  new ADR; `unsafe-eval` stays forbidden in the main window.
- `freezePrototype` may conflict with libraries that patch built-in prototypes; such a conflict
  must be solved in the library integration, not by turning the flag off silently.
- Tauri's isolation pattern was not adopted yet; reconsider it when third-party plugins or
  rendered HTML results (`DumpNode` kind `html`) arrive.
